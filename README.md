# Hackspot — 사라진 11분

현재 버전: **1.0.0**

공개 주소 기본값: https://visionexperiencedeveloper.github.io/hackspot/

메일, 가상 사이트, 터미널의 기록을 연결해 누락된 관측 기록을 조사하는 한국어 단일 사건 게임입니다. React UI와 순수 TypeScript 게임 엔진으로 구성됩니다. 실제 서버 접속·명령 실행·메일 전송은 없습니다.

## 실행

Node.js 22.13 이상에서:

```sh
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. 개발 서버와 미리보기는 같은 포트를 사용하므로 동시에 실행하지 않습니다.

```sh
npm run build
npm run preview
```

## 플레이와 저장

1. 메일의 **조사 시작**을 누릅니다.
2. 브라우저의 공개 보고서·운영 공지·시민 교대 기록을 연결합니다.
3. 터미널의 `help 조사`로 명령을 확인하고 주소 조회 → 서비스 확인 → 접속 → 열람·수집을 진행합니다.
4. 세 증거를 `compare`로 대조한 뒤 메일에서 판단과 전달 경로를 제출합니다.

- Alt+1~6: 터미널·브라우저·메일·폴더·메모장·액셀. ↑↓: 명령 기록. Tab: 자동완성. Shift+Tab: 입력 밖으로 이동. Ctrl/Cmd+L: 터미널 출력 지우기. Escape: 대화상자·진행 패널 닫기.
- 상단 Hackspot 로고 오른쪽 끝의 점 세 개 버튼으로 진행 기록·힌트 패널을 엽니다. 패널은 앱 창 위에 떠서 표시되며 바깥 클릭, 닫기 버튼, Escape로 닫힙니다.
- 폴더는 Finder처럼 사이드바, 경로, 아이콘/목록 보기를 제공합니다. **새 폴더**, **이름 변경**, **이동**으로 정리하고 파일은 더블클릭 또는 **열기**로 연결된 앱에서 엽니다. 텍스트·로그는 메모장, `.eml`은 메일, `.csv`는 액셀로 열립니다.
- 메모장은 빈 편집 화면으로 열립니다. **저장하기**에서 저장 위치와 파일 목록을 탐색하고 파일 이름·형식을 지정합니다. 새 폴더를 만들거나 같은 이름의 파일을 덮어쓸 수 있습니다.
- 액셀에서 CSV의 셀을 클릭하거나 방향키로 이동해 셀 주소와 값을 확인할 수 있습니다.
- 작업 표시줄 왼쪽의 검색 아이콘으로 설치된 앱과 수집한 파일·대조표·개인 메모를 검색합니다. 앱 이름, 파일 이름·경로·본문으로 찾고 결과를 누르거나 ↑↓와 Enter로 엽니다. 아직 확보하지 않은 파일은 검색에 표시되지 않습니다.
- 작업 표시줄 시계는 브라우저의 현재 로컬 시각을 표시하며 자동 갱신됩니다.
- 작은 화면은 한 번에 한 창을 표시합니다. 작업 표시줄에서 앱을 전환합니다.
- 작업 표시줄에는 실행 중인 앱만 표시됩니다. 최소화는 탐색 위치·입력 초안을 유지하고 작업 표시줄에 남습니다. **X**는 앱을 완전히 종료하며 다시 열면 초기 화면입니다. 수집한 파일과 저장한 메모 파일은 유지하고, 터미널 세션·출력·명령 기록과 저장하지 않은 메모 초안은 종료 시 초기화합니다. 실행하지 않은 앱은 바탕화면, 검색, Alt+1~6로 엽니다.
- **새 게임**은 진행·메모 파일·폴더 구성·편집 초안을 초기화합니다. 글자 크기는 현재 화면의 설정으로 유지됩니다.
- 진행·증거·힌트·메모 파일·작업 중 메모 초안·명령 기록은 이 브라우저의 localStorage 단일 슬롯에 저장됩니다. 메모 파일은 최대 100개, 파일별 10,000자까지 지원하며 빈 폴더도 보존합니다. 주소와 창 배치 등 UI 상태는 새로고침 후 기본 상태로 돌아갑니다. 이전 v1 저장의 개인 메모는 편집 초안으로 이어집니다.
- 자동 저장은 250ms 동안 입력을 모아 쓰며, 새로고침/백그라운드 전환 때 미저장 변경을 반영합니다. 프로세스 강제 종료까지 보장하지는 않습니다.
- 손상/지원하지 않는 저장은 자동으로 덮어쓰지 않습니다. **나중에**를 누르면 임시로 조사할 수 있고 작업 표시줄의 **저장 안내 열기**에서 다시 안내를 열 수 있습니다. **이 세션 저장 시작**이나 **새 조사 시작**을 선택하면 현재 진행으로 교체됩니다.
- 저장 공간/권한 오류는 화면과 상태 표시로 알립니다. 공간/권한을 복구한 뒤 **저장 다시 시도**를 누릅니다. 브라우저 데이터 삭제나 다른 origin으로 이동하면 기존 기록을 사용할 수 없습니다.
- 이미 단서를 알고 있는 재플레이는 허용합니다. 공개 보고서와 원본 세 증거의 대조가 끝나면 자료 조사도 완료로 판정합니다. 정답과 콘텐츠는 클라이언트에 포함됩니다.

## 터미널 실습

로컬 셸의 `/home/analyst`는 폴더 앱의 **내 파일**과 같은 공간입니다. `ls`, `cd`, `mkdir`, `cp`, `mv`, `rm`, `find`로 정리하고 `cat`, `grep`, `head`, `sort`, `wc` 등으로 내용을 처리할 수 있습니다. `help`는 자주 쓰는 명령과 짧은 설명을 보여줍니다. `man grep` 또는 `help grep`으로 명령별 옵션과 실행 예시를 확인할 수 있습니다. 조사 순서는 `help 조사`, 파이프·리다이렉션·변수 사용법은 `help 문법`에 있습니다.

터미널은 기본 사용자 `analyst`의 프롬프트에서 시작합니다. `sudo su root`로 가상 관리자 셸에 들어가고 `exit`로 돌아옵니다. 가상 IP·인터페이스 설정을 변경하거나 1024 미만의 포트를 관리하려면 root 권한이 필요합니다. 루트 권한은 터미널을 닫거나 새로고침하면 해제됩니다.

아래 명령은 가상 인터페이스에 주소를 추가하고, 지정한 폴더를 HTTP로 제공한 뒤, 포트와 응답을 확인합니다.

```sh
mkdir -p lab
printf '%s\n' ready > lab/index.html
sudo su root
ip addr add 192.168.50.10/24 dev eth0
exit
serve --bind 192.168.50.10 8080 lab
ss -tuln
curl -i http://192.168.50.10:8080/
stop 8080
```

`ip -br addr`와 `ip route`로 주소와 경로를 확인하고 `ping`, `nc -zv`, `nmap -p`로 가상 호스트와 포트를 점검할 수 있습니다. IP와 실행 중인 가상 서비스는 브라우저를 새로고침해도 복구되며 **새 게임**에서 초기화됩니다. 조사 서버에 접속하면 기존 조사 명령과 읽기 전용 파일 탐색을 함께 쓸 수 있습니다.

셸과 네트워크는 브라우저 안에서 시뮬레이션됩니다. `help` 뒤에 공백을 입력한 뒤 Tab을 누르면 매뉴얼이 있는 명령을 찾아볼 수 있습니다.

## 구조

- `src/game/world.ts`: 사이트, 서버, 문서, 증거, 목표, 힌트.
- `src/game/engine.ts`: 명령 실행, 상태 전이, 제출 판정. 네트워크/DOM/실제 셸 접근 없음.
- `src/game/shell/`: 셸 구문, 파일 명령, 가상 인터페이스와 HTTP 서비스.
- `src/game/storage.ts`: v1 저장의 식별자·형식·상태 관계 검증.
- `src/hooks/`: 자동 저장, 게임 세션, 창 관리, 파일·휴지통 작업.
- `src/configs/`: 초기 창 배치 등 데스크톱 설정.
- `src/pages/`: 메일·브라우저·파일·메모·터미널·휴지통과 가상 사이트.
- `src/components/desktop/`, `src/components/common/`: 데스크톱 셸, 창 목록, 대화상자, 공통 UI.
- `src/styles/`: 페이지와 데스크톱 기능별 CSS. `src/styles.css`에서 기존 캐스케이드 순서로 불러옵니다.
- `src/App.tsx`: 세션과 앱 화면을 조립하는 진입점.
- `docs/DESIGN.md`: 시나리오·규칙·화면 설계와 구현/검증 대조표.
- `docs/cyber-investigation-campaign.md`: 난이도가 높아지는 50개 사이버 조사 사건의 상세 기획안. 실제 사건은 교훈 참고용이며 게임에 구현된 콘텐츠는 아닙니다.
- `docs/maintenance-roadmap.md`: 수정 이력과 향후 범위.
- [백엔드 개발 작업 매뉴얼](docs/backend-engineering-manual.md): 작업별 기본 참고 기준. 저장소 지침과 기존 구현을 먼저 확인하고 요청에 해당하는 절만 적용합니다.

현재 프로젝트는 브라우저에서 실행되는 정적 앱으로, 실제 백엔드·DB·인증·외부 API 및 필수 환경변수가 없습니다. 별도 환경 파일 없이 실행합니다. 매뉴얼의 서버 계층·Docker Compose·DB 백업·헬스체크 등은 해당 기능을 도입하는 작업에서 필요성을 판단합니다. 현재 적용되는 재현 가능한 설치, 입력·저장 검증, 자동 검사, 정적 배포·복구 기준은 기존 구현과 아래 절차를 따릅니다. 매뉴얼의 기술과 수치는 예시이며 이 프로젝트의 요구사항으로 일괄 적용하지 않습니다.

## 검사

```sh
npm run check
npx playwright install chromium webkit
npm run test:e2e
npm run test:hosting
npm audit
```

`check`는 ESLint, Prettier, Vitest, TypeScript 및 프로덕션 빌드를 실행합니다. E2E는 빌드된 앱을 127.0.0.1:4173에서 띄우고 끝나면 서버를 종료합니다. 이미 같은 포트에 서버가 있으면 로컬 실행은 이를 재사용하므로 최신 빌드인지 확인하세요. CI는 기존 서버 재사용을 허용하지 않습니다. `test:hosting`은 임시 포트에서 루트/하위 경로 정적 배포와 저장 재개를 검사합니다.

브라우저 실패 자료는 기본 `/tmp/echo-playwright-results`, 화면 캡처는 `/tmp/echo-*.png`에 생성됩니다. 테스트는 격리된 브라우저 컨텍스트를 사용합니다. 사용자의 실제 브라우저 저장을 초기화하지 않습니다.

## 검증 범위 (2026-11-05)

- 도메인·저장·창 경계·가상 셸 단위 테스트 47개와 lint·format·typecheck·프로덕션 빌드 통과.
- 브라우저 테스트 41개 통과. 모바일에서 제공하지 않는 데스크톱 드래그 검사 1개는 적용 제외이며 모바일 배치·전환은 별도 검증.
- Chromium 데스크톱 1440×900, Chromium 모바일 에뮬레이션 390×664, WebKit 1280×800에서 실제 UI를 통한 두 결말, 오답 재시도, 중간 reload, 증거/메모 복구.
- 최소화·닫기·복원·새 게임 초기화, 입력 기록·자동완성·지우기, 저장 오류·손상 복구, 모달 포커스·Escape·단축키 차단, 작은 화면·글자 확대, 데스크톱 이동·크기·최대화.
- Finder 새 폴더·이동·이름 변경, 파일 저장과 새로고침 후 복구, CSV를 액셀로 열어 셀 선택·방향키 이동을 확인했습니다. 정적 빌드의 루트·하위 경로에서 이름과 폴더를 지정한 메모 파일도 복구됐습니다.
- 터미널에서 파일을 만들어 폴더 앱에서 열고, 새로고침 후 가상 IP·포트와 HTTP 응답을 확인했습니다.
- IME는 composition/keyCode 229 이벤트와 조합 중 form submit으로 자동 검증합니다. 실제 OS 한글 입력기 및 실물 모바일 키보드 검증과는 구분합니다.
- 초회 **15~20분은 설계 목표**입니다. 신규 사용자의 실제 플레이 시간·난이도 검증은 아직 하지 않았습니다.
- GitHub Actions 검사 설정을 추가했지만 원격 저장소 연결과 원격 CI 실행, 공개 배포는 하지 않았습니다.

## 정적 배포와 변경 관리

배포 대상은 `dist/` 전체입니다. `base: './'`로 루트 또는 하위 디렉터리에 배치할 수 있습니다. HTTP(S) 정적 서버를 사용하고 HTML·JS·CSS·`ocean.png`가 같은 버전으로 배포되어야 합니다. 새 배포 전 `npm run check`, `test:e2e`, `test:hosting`을 통과시킵니다. 이전 산출물을 보관하면 정적 파일 묶음 단위로 복구할 수 있습니다. 공개 URL에서는 자산 로딩·새로고침·저장/재개를 다시 확인해야 합니다.

현재 v1의 정상 저장은 그대로 읽습니다. 향후 저장 형식을 바꾸면 별도 버전과 명시적 migration을 추가하고 기존 진행 샘플로 테스트해야 합니다. 미래 버전을 현재 버전으로 추정 변환하거나 손상된 저장을 자동 삭제하지 않습니다.

Git 변경은 `main` 브랜치에서 관리하며 GitHub 원격 저장소에 게시합니다. `.gitignore`는 빌드, 의존성, 테스트 결과, 환경 파일을 제외합니다. `.github/workflows/check.yml`은 push/PR 시 정적·브라우저·호스팅 검사를 실행하도록 구성되어 있습니다.
