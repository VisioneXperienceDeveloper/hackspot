# 사이버 조사 캠페인: 50개 사건 기획

## 기획 원칙

- 50개 사건은 쉬운 기록 읽기에서 시작해 다중 조직·다중 시스템의 판단으로 난이도가 오르도록 배열한다.
- 실제 사건은 문제 유형과 교훈만 참고한다. 인물·기관·날짜·지명·증거는 허구로 재구성하며 특정 개인이나 조직에 책임을 돌리지 않는다.
- 취약점 사건은 격리된 가상 환경의 설정·로그·정책 증거를 분석하는 방식으로 다룬다. 실제 대상에 대한 침투 절차, 페이로드, 악성 코드 제작은 게임에 포함하지 않는다.
- 정답 암기보다 증거 출처, 시간대, 권한 범위, 대안 가설, 불확실성을 설명하는 능력을 평가한다.
- 각 의뢰는 유형에 따라 승인된 보안 점검, 침해 조사, 또는 권한이 불명확하거나 불법인 해킹 요청으로 분류한다. 요청의 현실감은 살리되, 허가 없는 침투를 수행하는 게임 흐름은 제공하지 않는다.
- 사건은 접수·범위 확인·도구 준비·자료 수집·분석·검증·보고·정리의 실무 흐름을 따른다. 필요하지 않은 단계는 억지로 넣지 않는다.
- 아래 난이도는 초회 플레이 기준의 설계값이다. 실제 플레이테스트 뒤 조정한다.

## 공유 세계관과 반복 사용 사이트

플레이어는 여러 기관의 의뢰를 받는 가상의 **공동 디지털 대응 데스크** 조사관이다. 메일, 사건 접수함, 데스크톱 앱, 도구 보관함은 모든 사건에서 공통으로 유지한다. 각 사건은 허구 도메인 `.test`와 특정 시점의 자료 사본만 사용한다.

| 기관·사이트                          | 정식 역할             | 관련 사건과 재사용 방향                                                         |
| ------------------------------------ | --------------------- | ------------------------------------------------------------------------------- |
| `haeon.test`                         | 해온 해양관측소       | 01의 보고서·수정 이력; 이후 수질 자료·센서 사건에서도 같은 기관을 재사용        |
| `tide.test`                          | 시민 관측·교대 기록   | 01의 공개 단서; 후속 사건에서 시민 제보·현장 기록을 제공                        |
| `archive.test`, `vault.archive.test` | 독립 기록원·원본 보관 | 01의 원본 저장소; 다른 사건에서는 같은 보존 정책과 감사 담당자를 참조           |
| `saebom.test`                        | 새봄의료원            | 02의 감사 의뢰; 18·33·43 등 의료기관 복구 사건에서 동일 기관을 재사용할 수 있음 |
| `roster.saebom.test`                 | 병원 근무표 시스템    | 현재 근무표와 버전 기록의 읽기 전용 사본                                        |
| `policy.saebom.test`                 | 병원 업무 규정        | 근무 교환·승인 절차                                                             |
| `audit.saebom.test`                  | 병원 감사 자료함      | 비식별 이벤트와 결재 대장 미러                                                  |

같은 사이트를 다시 쓸 때는 기관 ID와 URL을 유지하고 사건 날짜에 맞는 버전 스냅샷을 제공한다. 사건을 임의 순서로 플레이해도 기록이 모순되지 않도록 각 문서에 `caseId`, `validAt`, `capturedAt`, `version`을 둔다. 한 에피소드의 결말이 다른 에피소드의 자료를 조용히 바꾸지 않으며, 지속 결과가 필요한 경우 플레이어에게 변경 사항을 명시한다.

## 사건 유형과 공통 업무 흐름

각 사건은 아래 유형 중 하나 이상을 선언한다.

| 유형                    | 현실적인 단계                                                                                                                                      | 안전한 플레이 경계                                                                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 승인된 보안 점검        | 의뢰 확인 → 서면 승인과 범위 검증 → 승인 자산 목록 확인 → 가상 점검 도구 설치 → 사전 제작된 샌드박스 결과 분석 → 위험·영향 보고 → 수정 확인        | 대상은 해당 사건에 포함된 가상 자산뿐이다. 범위 밖 자산·실제 IP·실제 서비스에는 검사하지 않는다. 취약점 검증은 정해진 시뮬레이션 결과로 제공한다. |
| 침해·이상행위 조사      | 신고 접수 → 자료 보존과 조사 권한 확인 → 영향 범위 분류 → 증거 출처·무결성 기록 → 타임라인·가설 분석 → 안전한 억제·복구 제안 → 사실·한계·통지 보고 | 로그·파일은 제공된 읽기 전용 사본을 쓴다. 실제 계정 로그인, 시스템 변경, 악성코드 실행은 없다.                                                    |
| 불법·불명확한 해킹 의뢰 | 의뢰와 대상 확인 → 승인 증거가 없거나 권한이 불분명한 점 식별 → 작업 보류·거절 → 증거 보존 또는 적법한 보안 점검·신고 절차 안내                    | 공격을 실행하거나 공격 도구를 설치하지 않는다. 거절·범위 재확인·사건 신고가 올바른 진행이며, 보복 침투도 허용하지 않는다.                         |

**공통 조사 루프:** ① 의뢰와 조사자 역할 확인 ② 권한·대상·시간·허용 행위·제외 범위를 명시 ③ 사건에 필요한 가상 도구 선택 ④ 자료 출처와 수집 이력을 보존 ⑤ 근거를 교차 분석 ⑥ 승인된 범위에서만 결과를 시뮬레이션으로 검증 ⑦ 사실·신뢰도·미확인 사항·대응 권고를 보고 ⑧ 도구와 사건 작업공간을 정리한다.

## 가상 프로그램 설치와 도구 세트

데스크톱에 공통 **도구 보관함(Toolbox)** 앱을 둔다. 도구는 플레이어가 목록에서 설치하는 가상 프로그램이다. 설치는 UI와 사건 상태만 바꾸며 파일 다운로드, 실제 바이너리 실행, 운영체제 권한 획득, 외부 네트워크 사용은 하지 않는다.

| 가상 도구       | 역할                                                          | 입력·출력 제한                                                                         |
| --------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `ScopeGate`     | 승인서, 날짜, 자산, 허용 행위와 제외 범위 확인                | 사건의 승인 메타데이터만 읽는다. 범위가 없으면 다른 도구 설치를 잠근다.                |
| `AssetMap`      | 승인된 가상 자산과 관계를 지도 형태로 표시                    | 사건에 포함된 자산 목록만 사용하며 네트워크를 탐색하지 않는다.                         |
| `ConfigLens`    | 제공된 설정·정책 스냅샷에서 방어상 위험을 분류                | 로컬 자료만 읽고 수정하지 않는다.                                                      |
| `VulnBench`     | 사전 제작된 취약점 실습 결과와 테스트 보고서를 열람           | 고정된 샌드박스 결과만 재생한다. 임의 페이로드·실제 공격 명령·대상 입력은 받지 않는다. |
| `ImpactSim`     | 승인된 샌드박스의 사전 정의된 시나리오에서 영향 범주를 시각화 | 실제 코드를 실행하거나 시스템 상태를 바꾸지 않고 합성 결과만 보여준다.                 |
| `RosterDiff`    | 근무표 CSV 스냅샷의 차이 비교                                 | 제공된 변경 전·후 파일만 처리한다.                                                     |
| `LogTimeline`   | 제공된 기록의 시각·출처를 정렬하고 사건표 생성                | 합성 로그만 읽으며 계정 사용자를 추정하지 않는다.                                      |
| `EvidenceVault` | 자료 출처, 수집자, 시각, 보존 상태를 기록                     | 읽기 전용 사본을 보관하고 원본을 변경하지 않는다.                                      |
| `ReportKit`     | 사실·추론·확신도·권고를 분리한 보고서 작성                    | 근거 없는 결론에는 경고를 표시한다.                                                    |

도구 카탈로그에는 게시자(가상), 버전, 로컬 카탈로그 출처, 무결성 상태, 요구 권한, 입력·출력 자료, 허용 사건 유형을 표시한다. 설치 흐름은 세부 정보 확인 → 사건 범위 확인 → 카탈로그 무결성 확인 → 설치 승인 → 설치 이력 기록 → 실행·수집 → 작업 종료·제거 순서다. `ScopeGate`는 기본 제공하고, 나머지는 사건 목적에 따라 설치한다. 잘못된 의뢰에서는 `ScopeGate`와 안전한 신고·보존 기능만 제공하고 점검·검증 도구는 잠근다. 이 흐름은 실제 패키지 다운로드나 셸 명령을 호출하지 않는다.

### 실제 포렌식 도구를 이용하는 선택형 오프라인 실습

게임 밖의 선택형 학습 자료에는 실제 포렌식 프로그램을 사용할 수 있다. 사용자는 프로그램을 공식 배포처에서 별도로 설치하고, 게임이 제공하는 비식별 샘플을 로컬에서 직접 연다. 정적 브라우저 앱은 네이티브 앱을 설치·실행하거나 결과를 자동 수집하지 않는다.

| 실제 프로그램 | 허용되는 학습 흐름                                                                                               | 샘플·경계                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Wireshark     | 제공된 패킷 캡처 파일을 열고 캡처 시각·프로토콜 요약·통신 흐름을 검토한 뒤, 관련 이벤트와 한계를 보고서에 기록   | 합성·비식별 `.pcapng`만 사용. 실시간 캡처, 패킷 전송·주입, 인증정보 수집은 범위 밖      |
| Autopsy       | 제공된 읽기 전용 디스크 이미지로 사건을 만들고 파일 메타데이터·타임라인을 검토해 관련 증거 ID와 판단 근거를 기록 | 합성 이미지와 명시적 매니페스트만 사용. 실제 장치 수집, 사용자 자료 복구·반출은 범위 밖 |

샘플 묶음에는 사건 ID, 출처, 허용 분석, 버전, 무결성 확인값, 개인정보·악성 콘텐츠 검토 여부를 기록한다. 시나리오 14·19·31에는 합성 패킷 자료를, 18·33·43에는 합성 디스크 이미지를 선택적으로 제공할 수 있다. 사건 02에는 패킷 캡처나 디스크 이미지가 없으므로 Wireshark·Autopsy를 설치하는 대신 근무표·로그 전용 도구를 고른다.

### 능동 공격 도구의 처리

Nmap, Bettercap, Hashcat처럼 실제 대상에 대한 탐색·가로채기·자격 증명 공격에 사용될 수 있는 프로그램은 게임 안에서 실행하거나 실제 사용 명령을 재현하지 않는다. 관련 학습 목표는 다음과 같은 안전한 결과 자료로 대체한다.

- 자산 탐색은 승인된 가상 자산 목록과 미리 생성한 발견 결과를 읽고 범위 누락을 검토한다.
- 네트워크 관측은 사전에 만든 합성 패킷 캡처를 Wireshark로 분석한다. 실시간 중간자 동작이나 트래픽 가로채기는 제공하지 않는다.
- 비밀번호 감사는 실제 해시나 크래킹 작업 대신 합성 감사 요약과 정책 개선 결과를 검토한다.
- 취약점 검증은 `VulnBench`의 고정 사례와 `ImpactSim`의 사전 계산된 결과로만 표현한다. 도구별 공격 명령·페이로드·실제 표적 입력은 제공하지 않는다.

따라서 Nmap은 실행 가능한 스캐너가 아니라 사전 생성된 가상 자산 목록으로, Bettercap은 설치·실행 없이 오프라인 캡처 분석으로, Hashcat은 해시 입력이나 크래킹 없이 합성 비밀번호 감사 결과로 학습한다.

| 사건                | 작업 유형                            | 권장 가상 도구                                                                            |
| ------------------- | ------------------------------------ | ----------------------------------------------------------------------------------------- |
| 01–20               | 사건 조사·업무 기록·계정 이상 확인   | `EvidenceVault`, `LogTimeline`, 필요한 사건의 `RosterDiff`, `ReportKit`                   |
| 21–30               | 승인된 설정·권한 설계 평가           | `ScopeGate`, `AssetMap`, `ConfigLens`, 샌드박스 한정 `VulnBench`·`ImpactSim`, `ReportKit` |
| 31–36, 38–39, 41–50 | 복합 침해 대응·복구·영향 평가        | `ScopeGate`, `EvidenceVault`, `LogTimeline`, `AssetMap`, `ReportKit`                      |
| 37                  | 허가 없는 보복 침투 요청과 증거 혼합 | `ScopeGate`, `EvidenceVault`, `LogTimeline`, `ReportKit`; 공격 기능은 제공하지 않음       |
| 40                  | 책임 있는 취약점 제보와 공개 조율    | `ScopeGate`, `EvidenceVault`, `ConfigLens`, `ReportKit`; 승인 전 재현은 금지              |

| 2단계 · 기초 조사 | 11–20 | 피싱·계정·클라우드 흔적, 출처 비교, 초기 대응        |

각 사건의 결말은 단순 정답/오답이 아니라 증거에 부합하는 결정과 그 한계를 보여준다. 난이도가 높아질수록 조사 화면, 시간 압박 대신 정보량·상충하는 증거·영향 범위를 늘린다.

## 1단계 · 입문

- **반전·판정:** 영상 제작자를 특정할 충분한 증거는 없지만 내용은 허위다. 검증된 공식 안내를 빠르게 배포하고 확인되지 않은 귀속 주장은 보류한다.

### 47. 관리 서비스의 단일 장애점 — 난이도 9/10

- **역량:** MSP 위협 모델링, 공통 계정·원격 관리 범위 분석.
- **상황·조사:** 여러 고객사가 비슷한 경보를 보고한다. 관리 업체의 접근 방식, 고객별 분리, 변경 창, 각 조직의 독립 로그를 안전하게 조정한다.
- **반전·판정:** 공통 서비스가 관련됐더라도 고객 피해는 제각각이다. 모든 고객의 일괄 차단 대신 고객별 확인·격리·지원 절차를 마련한다.

### 48. 서로 맞지 않는 신고서 — 난이도 10/10

- **역량:** 불완전 증거에서 보고서 작성, 이해관계자 조율.
- **상황·조사:** 기술팀은 제한된 접근을, 경영팀은 전체 유출을, 공급자는 사고 없음을 주장한다. 원본 로그, 계약상 정의, 시간대, 검증되지 않은 진술을 분리한다.
- **반전·판정:** 단일한 완결 서사는 아직 없다. 확인된 최소 사실, 경쟁 가설, 추가로 필요한 자료, 각 대응의 위험을 함께 보고한다.

### 49. 세 갈래의 원인 — 난이도 10/10

- **역량:** 복합 사고 분해, 상관관계와 인과관계 구분, 자원 배분.
- **상황·조사:** 같은 날 피싱 신고, 클라우드 설정 오류, 내부 자료 수정이 발생한다. 로그상 연결되어 보이지만 각기 다른 원인일 수 있다.
- **반전·판정:** 조사 도중 피싱과 수정은 별개 사건으로 드러나고, 실제 피해는 설정 오류에서 발생한다. 사건을 분리하고 한정된 대응 인력을 위험도에 따라 재배치한다.

### 50. 검증 가능한 결론 — 난이도 10/10

- **역량:** 전체 조사 계획, 증거 사슬, 대응·복구·통지·윤리의 종합 판단.
- **상황·조사:** 핵심 공공 서비스에서 공급자 경보, 계정 이상, 데이터 변경, 이용자 제보가 동시에 들어온다. 플레이어는 조사 범위와 우선순위를 정하고 다른 팀에 필요한 자료를 요청한다.
- **반전·판정:** 모든 흔적을 하나의 공격으로 설명하는 답은 성립하지 않는다. 일부는 오탐, 일부는 설정 오류, 일부는 실제 무단 접근이다. 결말은 정답 이름이 아니라 증거에 맞는 조치, 놓친 위험, 남은 불확실성을 얼마나 투명하게 기록했는지로 결정한다.

## 구현 제안

- 50개를 한 번에 앱에 넣기보다 01–05를 시범 구현해 의뢰 승인, 도구 설치, 증거 보존, 힌트와 판정 구조를 검증한다.
- 사건 데이터는 본문·단서·목표·판정 기준·유형·승인 범위·허용 도구를 분리하고, 공통 사이트 레지스트리와 사건별 시점 스냅샷을 연결한다.
- `Toolbox`는 로컬 카탈로그와 가상 상태만 관리한다. 실제 실행 파일, 외부 다운로드, 임의 호스트 입력은 설계 범위에서 제외한다.
- 06 이후는 기존 사건의 플레이테스트 결과를 반영해 한 묶음씩 추가한다. 난이도는 기능 수가 아니라 증거의 신뢰도·상충 여부·영향 범위로 조정한다.
